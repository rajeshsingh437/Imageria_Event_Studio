Executive Overview

This document specifies the end-to-end Python technical architecture for sorting high-volume RAW images from school and university events into student-specific directories and applying precise, anatomy-based cropping for portrait generation. The production-verified architecture includes RAW ingestion (Stage 1), deep ArcFace clustering with centroid merge passes (Stage 2), dynamic golden-eye cropping (Stage 3), and a dedicated collage mosaic engine with 4-page PDF compilation (Stage 5).

The pipeline utilizes a dual-pillar framework of dynamic clustering and anatomy-based crop solving, engineered for autonomous execution. Version 2.0 incorporates Stage 1 RAW demosaicing and pHash culling, Stage 2 sequence continuity and group fan-out, Stage 3 symmetrical framing at 2160x3000 px resolution to prevent head/shoulder clipping, and Stage 5 Pillow-native A4 print-ready compilation.

Version 2.0 incorporates enterprise reliability hardening: DPDP Act 2023 biometric compliance, per-event calibration loops, pHash near-duplicate pruning, cluster-purity QA checks, relational state tracking, and dedicated convocation edge-case handlers (VIP mega-cluster exclusion, mortarboard/hood segmentation, and single-photo degradation).

Stage 1: Advanced RAW Ingestion, 16-Bit Color Space & Dual-Zone Color Correction

Technical Implementation

1. Hardware-Accelerated RAW Demosaicing: Ingests camera-native RAW formats (CR2, NEF, ARW) using rawpy (LibRaw) to extract uncompressed 14/16-bit linear sensor data, applying optimal debayering algorithms (AHD/PPG) and auto-normalizing white balance across diverse camera bodies.

2. Perceptual Hash (pHash) Pre-Filtering: Before dispatching frames to heavy GPU neural networks, computes 64-bit perceptual hashes (imagehash library) across sequential burst shots. Frames with Hamming distance ≤ 6 and near-identical exposure are flagged as near-duplicates, pruning up to 40% of redundant GPU inference cycles.

3. Pre-Press Color Management & CMYK Gamut Mapping: 

   * Utilizes LittleCMS (lcms2 / pyvips) to maintain a wide-gamut 16-bit working color space (ProPhoto RGB / Adobe RGB).

   * Applies perceptual rendering intent to map RGB colors into standardized print CMYK profiles (Coated FOGRA39 or US Web Coated SWOP), preventing harsh gamut clipping on saturated stage LED highlights, graduation hoods, and deep fabric tones.

4. Automated Horizon & Perspective Leveling: Detects the eye-line tilt angle using θ = arctan(Δy/Δx) to auto-rotate and straighten hand-held camera tilt before culling.

5. Two-Tier Max-Recovery Quality Culling & Zero-Frame Fallback: 

   * Evaluates global luminance histograms and Laplacian variance edge blur metrics.

   * Zero-Usable-Frame Policy: If every frame in a student's burst exhibits severe blur or closed eyes, the pipeline activates an explicit flag_best_available fallback, routing the highest-scoring candidate with a manual retouch tag rather than silently dropping the student.

6. Environment-Specific Dynamic Range Profiles: 

   * Outdoor Sports: Compresses blown-out sunny highlights (-1.5 EV to -2.0 EV) on white garments and lifts shadows (+1.0 EV to +1.5 EV) on shaded faces.

   * Indoor Auditoriums: Applies high-ISO spatial denoising (ISO 3200–6400) over low-light regions prior to face detection.

   * Backlit Stage & Spotlights: Compensates for strong overhead rim lighting and deep facial shadows using localized shadow lift (+1.8 EV) on skin polygons while compressing stage spotlight blowouts.

7. Dual-Zone Color Correction: 

   * Subject Zone: Isolates face and skin polygons via landmark feathering to neutralize unnatural stage LED/DJ color casts (red, magenta, cyan), restoring natural skin tones.

   * Background Zone: Retains the vivid ambient stage lighting atmosphere using feathered alpha mattes.

Stage 2: Unsupervised Student Identification, Anchor Selection & Cluster Asset Routing

Technical Implementation

1. Deep Facial Embedding Extraction: Generates normalized 512-dimensional feature vectors using InsightFace ArcFace (Buffalo_l backbone) on GPU for every detected face across all event folders.

2. VIP Dignitary Mega-Cluster Exclusion Pass: 

   * In convocation events, dignitaries (Director, Dean, Chief Guest) appear in hundreds of handshake frames, creating massive "mega-clusters" that distort similarity matching.

   * The engine automatically calculates median cluster size across the cohort and flags/excludes any statistical outlier cluster (> 3× median size) or known dignitary reference embedding from student memoir assignment.

3. Multi-Context Sub-Clustering & Cross-Context Re-ID: 

   * Photographs from disparate event sub-contexts (indoor stage spotlight, outdoor family photos, sports action) exhibit distinct lighting and pose distributions.

   * The engine clusters images within each visual sub-context independently first, then executes a cross-context centroid re-identification pass to merge same-student clusters across different lighting environments without inducing false positive merges.

4. Unsupervised Density Clustering (Zero Pre-Defined ID Dependency): Computes a cosine distance matrix (1 - Cosine Similarity) using HDBSCAN to dynamically group images into distinct student clusters. Deterministic cluster IDs (Cluster_Student_001, Cluster_Student_002) are provisioned automatically.

5. Cluster-Purity QA Check: 

   * Evaluates intra-cluster variance: if the maximum pairwise cosine distance within a cluster exceeds 0.42, the cluster is flagged with cluster_split_risk and routed to the operator UI for mandatory visual spot-checking before PDF compilation.

6. Per-Event Similarity Calibration Loop: 

7. 3-Step Cluster Split Resolution Architecture: 

   * Best-of-Cluster Multi-Pose Comparison: Replaces single-anchor matching with max cosine similarity across all existing poses in the active student cluster (Match Score = max(v_new . v_i)). This prevents splits caused by extreme yaw, head tilt, or glasses reflections.

   * Temporal Sequence Continuity Check: Enforces session burst cohesion for consecutive photos within a 5-photo window.

   * Global Cluster Centroid Merge Pass: A secondary reconciliation pass that compares contiguous cluster centroids and automatically merges adjacent folders with similarity >= 0.48 into a single unified student directory.

   * Replaces hardcoded global cutoffs with an automated calibration pass using 50–100 sample candidate pairs from the current event dataset.

   * Calculates empirical distance distributions to calibrate exact strict match (S_strict) and borderline review (S_borderline) thresholds tailored to the specific camera sensors and venue lighting.

8. Multi-Factor "Best Among Equals" Anchor Scoring Engine: Evaluates all solo portraits in a student's cluster using a weighted quality scoring formula to lock anchor_hero_portrait.jpg:

   * Facial Pose & Symmetry (30%): Prioritizes square-on frontal poses (Yaw ≈ 0°, Pitch ≈ 0°). Degrades gracefully to moderate yaw (15°--30°) if only off-angle stage camera frames are available.

   * Eye Openness & Focus (25%): Evaluates Eye Aspect Ratio (EAR) and localized Laplacian iris sharpness to guarantee zero blinks.

   * Expression & Smile Assessment (25%): Evaluates mouth landmark ratios to select natural, authentic smiles while penalizing mid-speech or awkward mouth shapes.

   * Exposure & Lighting Balance (20%): Evaluates luminance distribution on skin polygons to favor balanced exposures over harsh flash hotspots or deep shadows.

9. Anchor Hero Placement & Occlusion Safeguards: 

   * Single-Subject Verification: Rejects any image containing >1 prominent face to keep group shots out of solo portrait slots.

   * Aspect Ratio Priority: Prefers native vertical images (Height > Width) for Page 2, using horizontal images only as a secondary fallback with dynamic cropping.

   * Resolution Threshold: Enforces minimum pixel density (300 DPI at print dimensions).

   * Tassel & Spectacle Glare Intercept: Detects graduation cap tassels occluding eye landmarks and filters out frames with harsh anti-reflective spectacle glare before selecting the hero anchor.

10. Ceremony Call-Order Timestamp Cross-Check: Where public convocation programs or department sequences are available, the pipeline cross-references cluster creation timestamps against sequence order as a high-confidence secondary validation signal.

11. Adaptive Similarity Thresholding & Asset Routing: 

   * Auto-Approved Match (Sc ≥ S_strict, calibrated ~ 0.52--0.55): Direct routing to /matched_events/cluster_ID/.

   * Borderline Match (S_borderline ≤ Sc < S_strict, calibrated ~ 0.38--0.51): Routed to /review_queue/cluster_ID/ for 1-click operator verification.

   * Non-Match (Sc < S_borderline): Sent to /unassigned/ pool.

Stage 4: Retouching Calibration, Anomaly Elimination & Micro-Face Association

4.1 Multi-Face Group Fan-Out, Association & Centroid Profiling

1. Multi-Anchor Centroid Profiling: Extracts 512-d vector embeddings from 3 to 5 high-confidence reference photos per student cluster and averages them to build a Centroid Profile Vector (V_p):

   * $$V_p = \frac{1}{K} \sum_{k=1}^K V_k$$

2. Single-Photo Profile Graceful Degradation: 

   * For students with exactly 1 usable photo (e.g., stage handshake only), multi-anchor centroid averaging is unavailable.

   * The engine degrades to single-vector matching with a tightened threshold margin and attaches an automatic single_photo_profile audit flag for operator visibility.

3. Calibrated Similarity Metric & Look-Alike Routing: 

   * $$S_c = \frac{V_d \cdot V_p}{\|V_d\| \|V_p\|}$$

   * Strict Match (Sc ≥ S_strict): Auto-copy to student cluster directory.

   * Uncertainty / Look-Alike Boundary (S_borderline ≤ Sc < S_strict): Automatically routes candidate to operator queue.

   * Rejection (Sc < S_borderline): Discarded.

4. Face Quality Indexing (FQI): Filters out low-quality detections before running vector similarity. Rejects faces smaller than 32 × 32 pixels or with yaw/pitch angles > ± 45°.

5. High-Res Micro-Face Slicing (SAHI): Slices high-resolution event photos (>4K) into smaller overlapping tiles before running face detection to reliably locate small background faces in wide auditorium and stage crowd shots.

6. Multi-Face Group Photo Fan-Out Architecture: The pipeline scans group frames to extract all face vectors and automatically copies the single image into the directories of every student recognized with a similarity score Sc ≥ 0.55.

7. Micro-Face Super-Resolution & Restoration: When extracting small or distant faces from wide group shots for collage placement, applies CodeFormer with a subtle fidelity weight (≈ 0.35). This reconstructs crisp, print-ready facial features and irises while strictly preventing artificial hallucination of identity.

8. De-Duplication Engine: Prevents copying the same event photo into a student directory multiple times if the student appears twice (e.g., in mirror reflections or dual detections).

    # Broadcast mask across 3 color channels to blend 100% original eyes/glasses

    mask_3c = cv2.merge([mask, mask, mask])

    return (original_bgr * mask_3c + restored_bgr * (1.0 - mask_3c)).astype(np.uint8)

def reinject_skin_texture(original_bgr, restored_bgr, blend_strength=0.35, blur_radius=5):

    # Frequency separation using Gaussian low-pass subtraction

    low_freq = cv2.GaussianBlur(original_bgr, (0,0), blur_radius)

    high_freq = cv2.subtract(original_bgr.astype(np.int16), low_freq.astype(np.int16))

    retextured = cv2.add(restored_bgr.astype(np.int16), (high_freq * blend_strength).astype(np.int16))

    # 60-70% original blend to teeth/lips to avoid uncanny valley

    return np.clip(retextured, 0, 255).astype(np.uint8)

Production Infrastructure, Reliability & Data Governance

1. Data Governance & DPDP Act 2023 Compliance

* Consent Gatekeeper: Ensures parental/student consent is logged before processing biometric vectors.

* Encryption at Rest: All 512-dimensional facial embeddings stored in PostgreSQL/FAISS are encrypted using AES-256 keys.

* Automated Retention & Deletion: Retains biometric embeddings for a maximum of 90 days post-printing, after which embeddings are automatically purged.

* Opt-Out Routing: Instant deletion route that purges a student's facial embeddings and excludes their assets from unsupervised clustering upon request.

2. Relational State Tracking & Recovery Architecture

Replaces fragile folder scanning with a centralized relational database schema:

* images (id, file_path, phash, demosaic_status, created_at)

* clusters (id, cluster_label, centroid_vector, purity_score, is_vip, status)

* cluster_members (image_id, cluster_id, similarity_score, is_anchor)

* review_queue (id, cluster_id, image_id, flag_reason, locked_by, locked_at, status)

* decision_audit_logs (id, operator_id, item_id, action_taken, before_state, after_state, timestamp)

* render_jobs (id, cluster_id, pdf_path, print_status, updated_at)

3. Task Queue, Concurrency & Monitoring

* Celery + Redis / RabbitMQ: Dedicated worker pools separate I/O RAW reading, GPU embedding inference, and PDF rasterization.

* Exponential Backoff & Retries: Automatic retries on transient GPU out-of-memory errors with backoff intervals ([5s, 30s, 120s]).

* Dead-Letter Queue (DLQ): Unrecoverable corrupt files are routed to a DLQ with automated alert notifications.

* Queue Alerting: Real-time Slack/email alerts trigger when the review queue exceeds 50 pending items.

4. Hardened Operator Fallback & Infrastructure Stack

Task Queue & Concurrency Control:

The pipeline utilizes Celery + Redis to manage distributed processing tasks, replacing fragile file-arrival triggers. An item-locking claim mechanism prevents race conditions; images are locked in the database upon opening by an operator and released only on "Save" or after a 10-minute idle timeout.

Operator UI & Audit Logs:

The review interface (Streamlit/Label Studio) provides a full-cluster context view, displaying the candidate image alongside all other assets in the student cluster to catch merge errors. Every operator action is recorded in persistent decision audit logs (ID, timestamp, before/after states) to feed a calibration loop that tracks False Positive/Negative rates for threshold tuning.

Darktable Fallback & Spot-Check Protocol:

Images meeting specific severity criteria (e.g., severe backlight, extreme blur, or identity gate failure) are routed to a human operator for Darktable CLI manual processing. Human spot-checks are conducted based on a sampling plan tied to match confidence scores.

Queue Prioritization & Reversibility:

The review queue is ordered dynamically based on downstream print deadlines and similarity confidence. A late-correction window allows for single-page re-imposition and print-run reversals prior to final binding.

5. Unvalidated Darktable Fallback & Spot-Check Protocol

If automated processing triggers severity criteria, images are routed to the Darktable fallback for manual intervention. Human spot-checks are conducted using defined severity sampling.

6. Late-Correction / Reversibility Window

A minimal-cost single-page re-imposition window is established before the full print run to allow for final corrections.

* Item Locking / Claim Mechanism: Prevents race conditions when multiple operators work the review queue concurrently.

* Full-Cluster Context View: UI displays the entire candidate cluster alongside the flagged image to catch cluster-merge errors immediately.

* Queue Prioritization: Orders review queue by downstream print deadline and confidence distance.

* Calibration Feedback Loop: Logs operator accept/reject actions to continuously recalibrate similarity cutoffs for subsequent events.
